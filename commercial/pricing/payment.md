## USDC on Polygon (For Crypto-Native Customers)

### Setup (Polygon mainnet)

```bash
# 1. Generate a new wallet (cold wallet for receiving)
cast wallet new

# 2. Export only the public address (never the private key to any server)
cast wallet address --private-key 0xYOUR_PRIVATE_KEY

# Save the address: 0xAbC123...
```

### Delivery flow

1. Customer emails `pay@liangyu5.example.com` with "USDC payment for Polymarket Toolkit"
2. Reply with:
   - Amount: 99 USDC (~$99 at time of email, or fix to $99)
   - Address: `0xAbC123...` (Polygon)
   - Note: "Send exact amount. Include your email as transfer memo."
3. After confirming on-chain:
   - Send zip via WeTransfer / private GitHub release
   - Send license key via email
   - Add to Discord manually

### Pricing in USDC

Use a fixed USD amount, not a floating USDC amount (to avoid "I paid $100 when it was $99" disputes).

```python
# Rough conversion (don't use in production)
import requests
resp = requests.get("https://api.coingecko.com/api/v3/simple/price",
                    params={"ids": "usd-coin", "vs_currencies": "usd"})
usdc_price = resp.json()["usd-coin"]["usd"]  # ~1.00
usdc_amount = 99 / usdc_price  # 99 USDC
```

Or just tell customer: "Send approximately 99 USDC. I'll confirm and refund any overpayment."

### Anti-fraud note

- Always wait for 1 block confirmation before sending goods (Polygon ~2 seconds)
- Keep a spreadsheet: `email | tx_hash | amount | date | license_key | delivered`
- USDC transfers are reversible in some cases (USDC Blacklist) — wait 24h before fulfilling if amount > $500

### How it actually works (Creem License API)

We use **Creem's hosted License API**, not a homegrown HMAC. The flow
on every `--live` run:

```python
# tools/verify_license.py — abbreviated
import os, sys, json, requests, platform, uuid

CREEM_API_BASE = os.environ.get("CREEM_API_BASE", "https://api.creem.io")
CREEM_API_KEY  = os.environ.get("CREEM_API_KEY", "")  # founder's public key
LICENSE_KEY    = os.environ.get("POLY_PRO_LICENSE_KEY", "").strip()

def require_pro_license():
    if "--dry-run" in sys.argv or os.environ.get("DRY_RUN") == "1":
        return  # dry-run is always free
    if not LICENSE_KEY:
        raise RuntimeError("POLY_PRO_LICENSE_KEY not set — see README #-get-the-toolkit")
    # First run on this machine: activate (gets instance_id).
    # Subsequent runs: validate (cheaper, may use local cache offline).
    instance_name = f"{platform.node()}-{uuid.getnode()}"
    resp = requests.post(
        f"{CREEM_API_BASE}/v1/licenses/activate",
        json={"key": LICENSE_KEY, "instance_name": instance_name},
        headers={"x-api-key": CREEM_API_KEY},
        timeout=10,
    )
    resp.raise_for_status()
    if resp.json().get("status") != "active":
        raise RuntimeError("License not active (expired / revoked / device limit)")
```

- **Key format:** `ABC123-XYZ456-XYZ456-XYZ456` (4 segments joined by
  dashes, server-issued by Creem).
- **Issuance:** Creem auto-generates per order. You cannot mint them
  yourself; revoke them from Creem dashboard → Orders → license key.
- **Activation limit:** you set `3 devices per license` in the
  product Addons → License Key Management panel. The 4th device gets
  HTTP 403.
- **Expirations:** set to `Never expires` in the same panel (one-time
  purchase model).
- **Refund flow:** click "Refund" in Creem dashboard; the license
  automatically flips to `disabled`; next `validate` call rejects.
- **Validation offline:** `tools/verify_license.py` caches the
  instance_id locally so we don't hit Creem on every CLI invocation.
  On network error it trusts the cache for one offline grace period.

### Why this beats a homegrown HMAC

| Homegrown HMAC | Creem License API |
|---|---|
| Keys live in your repo's `.env`; if HMAC secret leaks, attacker can mint unlimited keys | Keys live in Creem's vault; only Creem can mint |
| Refund = manually tell buyer to delete a `.env` line | Refund = Creem flips status to `disabled`; next validate rejects |
| Activation limit = unenforceable (just copy the key) | Activation limit = enforced server-side; 4th device gets HTTP 403 |
| Audit trail = none | Audit trail = every activate/validate is in Creem dashboard |
| Buyer can share key with 100 people | Buyer can only use N devices; sharing gets blocked |

Cost: one online `validate` call per `--live` run. (Mitigated by local
instance_id cache + offline grace period.)

### .env.example (commits to the repo)

```bash
# Dry-run never reads these. Live mode requires both.
POLY_PRO_LICENSE_KEY=        # buyer-only — comes from Creem purchase email
CREEM_API_KEY=creem_pub_validate_xxxxxxxxxxxx   # public — founder-pinned
```

The `CREEM_API_KEY` value above is the founder's **public
validate-only** key (Creem issues these with the smallest scope
possible). The same value is committed to `.env.example` in the
public repo; that's expected and safe — it can validate any key but
cannot mint new ones.
